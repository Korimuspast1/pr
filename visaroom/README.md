# visaroom — Android

Нативное Android-приложение (Java, только Android Framework, без сторонних библиотек).
Package: `lav.visaroom.alav`, min Android 8.0 (API 26).

Экраны: вход / регистрация по email и паролю → главный экран с нижней навигацией:
**Chats** (официальный канал visaroom, поиск по чатам/каналам и @юзернеймам),
**Profile** (аватар, юзернейм, био, email и числовой ID 100000-5000000 — выдаётся
при регистрации) и **Settings** — настройки разложены по раскрывающимся папкам
**Chats**, **Notifications**, **Security**, **Privacy**, **Moderation** и
**Account**. Долгое нажатие на нижнюю кнопку **Settings** плавно открывает
окно аккаунтов: на одном устройстве можно держать до трёх аккаунтов и
переключаться между ними. Профиль человека открывается по тапу на его
имя/аватар в поиске и в чате. Аккаунт-администратор (по email владельца,
проверяется и в правилах) открывает профиль через поиск или
**Settings → Moderation** и может там — в том числе на своём профиле —
заблокировать аккаунт, выдать или снять галочку verified, поставить любой
положительный ID до 999999999999 (автоматическая выдача при регистрации
по-прежнему 100000-5000000), убрать юзернейм, очистить био и удалить фото.
Обычный пользователь начинает без галочки и не может включить её сам.
Второй пароль хранится только как PBKDF2-хэш в отдельном owner-only
документе `users/{uid}/security/twoFa`; в основном профиле его больше нет. Кнопка Message в профиле
открывает личный чат по собственному протоколу **VRProto** (протокол сообщений 2 со сквозным шифрованием) поверх HTTPS и
Firestore: история лежит глобально в `chats/{chatId}/messages/{messageId}`,
а у каждого участника — облачный индекс `users/{uid}/chats/{chatId}`.
Текст сообщений и черновики локально не сохраняются; приложение держит их
только в памяти и быстро подтягивает изменения из облака. Это собственная
реализация в духе MTProto для Firebase без отдельного VPS, а не серверный
протокол Telegram. В личном чате можно отправить файл любого типа до 25 МБ:
VRProto делит его на части по 600 КБ в Firestore, поэтому Storage/Blaze
по-прежнему не нужен. Для экономии облака у файла есть счётчик Downloads:
каждый из двух участников может полностью скачать его один раз; прерванное
скачивание слот не тратит, а при 2/2 части и метаданные автоматически
удаляются из Firestore (само сообщение с именем файла остаётся в истории).
В **Settings → Chats → Appearance** можно выбрать **System**, **Light** или
**Dark**: тёмная тема применяется ко всему приложению, а отдельный фон области
сообщений и обои личного чата продолжают работать поверх неё. Только
аккаунт администратора может писать в официальный канал visaroom прямо из
приложения; у обычных пользователей поле ввода остаётся заблокированным, а
правила Firestore дополнительно разрешают создание announcement только
администраторскому Firebase email. Для каждого личного чата можно поставить свои обои только себе, предложить
их собеседнику или сделать оба действия; собеседник сам нажимает Set
wallpaper, насильно его фон не меняется. Своё текстовое сообщение можно
изменить по долгому нажатию, а любое своё сообщение — удалить для обоих
участников; при удалении файла его облачные части тоже удаляются. Внутри
официального и личного
чата есть поиск по сообщениям. Язык интерфейса выбирается в настройках (английский, русский, украинский и дополнительные локали), а дизайн — чёрно-белый
liquid glass: закруглённые полупрозрачные серо-белые стеклянные панели без
верхней бликовой плашки, плавающая навигация и пузыри сообщений; кнопки,
строки и пузыри при нажатии плавно уменьшаются и пружинно возвращаются.
Иконки — свои vector-drawable
(аналог SVG в Android).

## Что нового в 1.11 и как работает E2EE

- Личные сообщения протокола 2, ответы на сообщения, приватные метаданные файлов/голосовых сообщений, сами фрагменты файлов и предложенные обои шифруются на устройстве до загрузки в Firestore. В базе остаются шифротекст, публичные ключи, подписи, обёрнутые ключи сообщений и метаданные чата (участники, время, ID и размер), но не открытый текст новых личных сообщений. Администратор проекта не получает приватных ключей участников и не должен мочь прочитать содержимое протокола 2 из Firestore.
- Приватные ключи хранятся на устройствах и локально шифруются ключом Android Keystore. Публичные ключи публикуются в `e2eeKeys/{uid}`. Необязательная резервная копия приватной идентичности хранится только как шифротекст в owner-only `users/{uid}/security/e2eeBackup` под отдельным паролем восстановления. Если потеряны все устройства и пароль резервной копии, старая зашифрованная история может стать недоступной; сброс ключей создаёт новую идентичность.
- Приложение закрепляет публичный ключ идентичности собеседника при первом использовании. При смене ключа отправка блокируется, пока пользователь не проверит код безопасности и явно не примет новый ключ. Это E2EE с долгоживущими/восстанавливаемыми ключами, а не Signal Double Ratchet с forward secrecy.
- Сообщения, созданные до 1.11, не становятся зашифрованными задним числом автоматически для всех: обновлённое приложение помечает legacy-сообщения и по мере возможности переписывает собственные старые текстовые сообщения отправителя в протокол 2 при открытии чата, когда ключи обоих участников доступны. Старые файловые фрагменты не переписываются автоматически, потому что слот загрузки может уже быть использован.
- В чате добавлены голосовые сообщения, свайп влево для ответа, фирменное стеклянное меню долгого нажатия, анимация испарения при удалении, плавное появление букв при вводе и ускоренная отправка. Тап по строке чата сразу открывает переписку. Подпись VRProto из шапки чата убрана.
- Уведомления о входящих сообщениях работают через foreground-проверки, пока процесс приложения жив, и периодический Android JobScheduler. Из-за выбранной архитектуры Firebase-only без собственного сервера и без отправителя FCM мгновенный push после принудительного завершения процесса не гарантируется; Android и оптимизация батареи могут отложить фоновую проверку. Для протокола 2 в облачном превью и уведомлении используется общий текст о зашифрованном сообщении.
- В самом низу Settings отдельно открывается большое Пользовательское соглашение. Язык приложения выбирается в Settings → Chats → Language.
- **Порядок обновления:** опубликовать полные правила 1.11 и сразу установить APK 1.11 на устройства. После публикации новых правил старые клиенты больше не смогут создавать plaintext-сообщения личных чатов, поэтому затягивать переход между Publish и обновлением приложения не стоит.

Профили и поиск по юзернеймам заработают в облаке после деплоя обновлённых правил
из `../firebase`. При регистрации, входе и каждом открытии приложения оно
само создаёт/чинит документы пользователя в Firestore: `users/{uid}`,
`profiles/{uid}`, `publicIds/{publicId}` (и, когда 2FA настроена,
`users/{uid}/security/twoFa`), а после сохранения юзернейма —
ещё и `usernames/{usernameLower}`; поэтому новые пользователи появляются во
вкладке Firestore **Data**. Без правил профиль сохраняется на устройстве.
Email в поиске не показывается: публичный каталог юзернеймов содержит только
юзернейм, ID и выданный админом признак verified.
Аватарки сжимаются до 256×256 и хранятся отдельным bytes-документом
`avatars/{uid}` в Firestore (не больше 120000 байт), поэтому Firebase Storage
и платный план Blaze для аватарок не нужны.

## Перед первым запуском — Firebase Console

Проект: `lool-4d49c` (конфиг — `app/google-services.json`).

1. Authentication → Sign-in method → включить **Email/Password**. Без этого вход не сработает.
2. Project settings → Android-приложение `lav.visaroom.alav` → Add fingerprint →
   SHA-1 подписи приложения: `DB:EE:4D:04:C5:8C:15:4A:5B:4F:24:F4:58:A6:65:39:C1:D4:56:F8`.
   Без этого Google может отклонять запросы с ошибкой «Requests from this Android
   client application are blocked» (API key ограничен зарегистрированным приложением).
3. Firestore Database → Create database (Production mode).
4. Опубликовать правила из папки `../firebase` в **Firebase Console**:
   - слева **Build → Firestore Database → Rules** — заменить весь текст
     содержимым `../firebase/firestore.rules` и нажать **Publish**;
   - **Firebase Storage не нужен**: аватарки хранятся в Firestore, поэтому
     платный Blaze для Storage включать не надо;
   - **Realtime Database приложение не использует**, создавать её только ради
     правил не нужно. Если такая база уже создана, открыть
     **Build → Realtime Database → Rules**, вставить
     `../firebase/database.rules.json` и нажать **Publish**.

   Вместо ручной вставки можно задеплоить все правила одной командой
   из папки `../firebase`:

   ```bash
   cd ../firebase
   npx firebase-tools deploy --only firestore:rules,database
   ```

Аккаунты создаются в обычном Firebase Auth. Приложение ходит в Firebase по официальному
REST API, поэтому Firebase SDK внутри APK нет — меньше кода, который можно вытащить.

## Сборка

Готовый подписанный APK: `../release/visaroom-1.11.0.apk` (подпись проверена apksigner,
workflow `Verify signed APK`).

R8-сборка идёт в GitHub Actions (`.github/workflows/build-apk.yml`). Если в репозитории
заданы секреты `VISAROOM_KEYSTORE_B64` (keystore в base64) и `VISAROOM_KEYSTORE_PASSWORD`,
CI сам подписывает APK и кладёт его в артефакт `visaroom-apk`. Без секретов CI собирает
unsigned APK в `build-transfer/` — он подписывается ключом владельца вне CI.

Локально (нужен JDK 17, Android SDK 34, Gradle 8.7):

```bash
gradle :app:assembleRelease
```

## Защита APK — что включено

- R8: обфускация имён классов/методов/полей, перенос классов в один пакет, оптимизация.
- Убраны имена исходных файлов и номера строк (`-renamesourcefileattribute`).
- `shrinkResources`, удалены все Log-вызовы, `debuggable=false`.
- Ключ Firebase и адреса API не лежат открытым текстом (XOR, `Vault.java`).
- Сессии (до трёх аккаунтов, refresh-token каждого) хранятся зашифрованными AES-256-GCM, ключ — в Android Keystore; локальный кэш профиля и файл аватарки у каждого аккаунта свои.
- `allowBackup=false`, данные исключены из бэкапа/переноса, только HTTPS.

Честно: на 100% «зашифровать» код клиентского приложения нельзя — APK всегда можно
распаковать (jadx/apktool), вопрос только в том, что там увидит человек. С этой сборкой
он увидит переименованные `a/b/c` классы без исходников и строк ключей. Настоящая защита
данных — не скрытность APK, а правила Firebase: приватные коллекции не
перечисляются, а немногие нужные `list`-запросы ограничены правилами
(каталог юзернеймов — 10, объявления — 50, свои чаты и сообщения — 100),
приватные документы читает только
владелец, публичные профили и аватарки отдаются по точному UID с учётом
приватности, а записи в чужие документы и служебные поля запрещены. Блокировка
аккаунта, ручная смена ID на любое положительное значение и галочка verified
доступны только админу и также проверяются правилами: владелец не может сам
снять блокировку, поменять себе ID вне автоматического диапазона или выдать
себе галочку. Личные VRProto-чаты и их сообщения читают только два участника;
индекс другого участника можно обновить только превью собственного
реального сообщения, нельзя подделать его отметку прочтения. Части файла
может читать только участник с неиспользованным слотом скачивания; каждый
может отметить только собственное завершённое скачивание, а удалить части
и метаданные правила разрешают после счётчика 2/2 либо отправителю при
удалении собственного файлового сообщения. Изменять текст и удалять
сообщение правила разрешают только его отправителю. Создавать сообщения
официального канала правила разрешают только администраторскому email;
обычные пользователи могут только читать announcements. Обои хранятся
приватно у владельца, и собеседник получает доступ только к изображению,
которое владелец явно отметил как предложенное для этого чата.

Не публикуйте вместе с APK:

- `mapping.txt` — он расшифровывает обфускацию обратно;
- `visaroom-release.p12` и пароль от него — без них нельзя выпустить обновление
  поверх уже установленного приложения.
