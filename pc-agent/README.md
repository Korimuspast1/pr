# pc-agent — управление компьютером из телеграма

Бот, который живёт **на вашем компьютере** и даёт вам полный контроль над ним из
телеграма: файлы, терминал, нагрузка, сон, перезагрузка, выключение.

> почему не на GitHub Actions: раннер — это чужой одноразовый контейнер, он
> умирает через 6 часов и вашего ПК не касается. Управлять компьютером может
> только процесс, запущенный на этом компьютере.

## быстрый старт (3 шага)

**1. токен.** Если у вас уже есть бот — берёте его токен. Важно: один токен —
один бот. Старый бот на этом токене нужно выключить, иначе Telegram будет
отдавать сообщения то одному, то другому и оба получат
`Conflict: terminated by other getUpdates request`.

**2. настройка.** Скопируйте `config.example.json` в `config.json` и заполните:

```json
{
  "token": "1234567890:AA...твой_токен",
  "allowed_chats": ["7415869150"],
  "workdir": ""
}
```

* `allowed_chats` — **обязательно**. Бот выполняет команды на вашей машине,
  поэтому работает только для этих chat_id, всем остальным отвечает «нет доступа».
* свой chat_id узнаете так: оставьте `allowed_chats` пустым, запустите агента,
  напишите боту `/start` — он пришлёт ваш id. Впишите его и перезапустите.
* `workdir` — корень, за пределы которого файловые команды не выходят.
  Пусто = домашний каталог.

**3. запуск.**

```bash
pip install requests
python run.py
```

Всё. Дальше пишете боту в телеграм.

## команды

| команда | что делает |
|---|---|
| `/dash` | живая карточка: CPU, RAM, диски, аптайм, топ процессов |
| `/ls [путь]` | что в каталоге |
| `/cat файл` | показать текст |
| `/get файл` | прислать файл в телеграм |
| `/put файл` (ответом на файл) | сохранить присланное на ПК |
| `/rm`, `/mkdir`, `/cd` | удалить (с подтверждением), создать, сменить каталог |
| `/sh команда` | выполнить (до 60 сек) |
| `/bg команда` | запустить в фоне, работает после закрытия чата |
| `/jobs`, `/log id`, `/stop id` | список задач, лог, остановить |
| `/procs`, `/kill PID` | топ процессов, убить процесс |
| `/stress 60` | нагрузить все ядра на 60 секунд |
| `/lock`, `/sleep` | заблокировать, усыпить |
| `/reboot`, `/shutdown` | перезагрузка и выключение — **через подтверждение кнопкой** |

## автозапуск

**Linux (systemd)** — чтобы жил всегда и поднимался после перезагрузки:

```bash
sudo cp pc-agent.service /etc/systemd/system/
sudo nano /etc/systemd/system/pc-agent.service   # поправить пути и пользователя
sudo systemctl enable --now pc-agent
journalctl -u pc-agent -f                        # смотреть лог
```

**Windows** — положите в автозагрузку ярлык на `start.bat`:
`Win+R` → `shell:startup` → скопировать туда ярлык.

**macOS** — `launchd` или просто «Настройки → Основные → Элементы входа».

## безопасность — прочитайте, это не формальность

Бот выполняет на вашей машине то, что вы напишете. Значит:

* **токен = доступ к компьютеру.** Кто получил токен и знает ваш chat_id —
  управляет вашим ПК. Токен, отправленный в переписку, считайте утёкшим:
  после запуска перевыпустите его у @BotFather (`/revoke`).
* **`allowed_chats` — ваша главная защита.** Никогда не ставьте `*` на постоянку.
* **опасные команды** (`rm -rf`, `mkfs`, `dd` на диск, fork-бомба, `shutdown`)
  не выполняются сразу — бот спрашивает подтверждение.
* **выключение и перезагрузка** — только после нажатия «да, точно».
* **файловые команды не выходят** за пределы `workdir`.
* запускайте от **обычного пользователя**, не от root/администратора.
  Так максимум, что можно сломать, — ваши файлы, а не систему.

## если что-то не так

| симптом | причина |
|---|---|
| `Conflict: terminated by other getUpdates request` | этот токен слушает кто-то ещё — старый бот ещё жив, выключите его |
| бот молчит | не задан `allowed_chats` для вашего id, или агент не запущен |
| `нет доступа` | ваш chat_id не в списке `allowed_chats` |
| `нет токена` | не заполнен `config.json` или не установлен `requests` |
| `/sh` не отвечает | команда идёт дольше 60 секунд — используйте `/bg` |

## секреты для запуска в облаке (GitHub Actions)

| секрет | обязателен | что это |
|---|---|---|
| `PC_AGENT_TOKEN` | да | токен бота от @BotFather |
| `YTDL_BOT_TOKEN` | запасной | тоже подхватывается, если первого нет |
| `PC_AGENT_ALLOWED` | нет | список chat_id через запятую; если не задан, берётся `allowed_chats.txt` |

workflow `.github/workflows/pc-agent.yml` стартует по cron каждые 10 минут,
по пушу и вручную. Новый прогон вытесняет старый, поэтому `Conflict` на одном
токене не возникает.

> в облаке агент управляет **контейнером GitHub**, а не вашим компьютером.
> для реального ПК запускайте `python run.py` на самом ПК.
