# sandboxOS — рабочий стол в браузере

Полноценный рабочий стол поверх сандбокса: панель сверху, док снизу, менеджер
окон (перетаскивание/ресайз/сворачивание/разворот), меню приложений (Super),
быстрые настройки, календарь, уведомления, блокировка экрана и настоящие
приложения, которые работают с реальной файловой системой и процессами.

Без зависимостей: только Node.js ≥ 18, `bash`, `curl`, `tar`/`zip`.

## Приложения

| приложение | что делает по-настоящему |
|---|---|
| **Браузер** (Firefox-style) | вкладки (Ctrl+T/W), закладки, история навигации, просмотр исходника, скачивание, поиск DuckDuckGo. Страницы тянет сервер через `curl`, HTML очищается до безопасного «read view» |
| **Терминал** | **настоящий PTY** (`pty.fork` → `bash -i`) + эмулятор **xterm.js**: работают `top`, `vim`, `nano`, `less`, `mc`, python-REPL, цвета 256/truecolor, курсор, resize. Отдельный пункт меню «Терминал (root)» открывает сессию сразу через `sudo -n` |
| **Файлы** | листинг, переходы, хлебные крошки, контекстное меню: открыть, скачать, переименовать, удалить, «открыть в терминале» |
| **Редактор** | чтение/запись реальных файлов, Ctrl+S, подсветка изменений |
| **Заметки** | markdown-файлы в `~/notes`, автосохранение, предпросмотр |
| **Изображения** | просмотр PNG/JPG из файловой системы, зум, скачивание |
| **Калькулятор** | собственный парсер выражений (скобки, %, √, память, история), клавиатура |
| **Системный монитор** | живой CPU/память/диск + таблица процессов с `kill` (TERM/KILL, через sudo в root mode) |
| **Анализ диска** | `du` по папкам, крупнейшие файлы через `find`, занятость раздела |
| **Архивы** | создание/распаковка `tar.gz` и `zip`, просмотр содержимого, скачивание |
| **Настройки** | обои, акцентный цвет, масштаб шрифта, часы, root mode, диагностика API, «О системе» |

Горячие клавиши: `Super` — меню приложений, `Ctrl+Alt+T` терминал, `Ctrl+Alt+F`
файлы, `Ctrl+Alt+B` браузер, `Ctrl+Alt+M` монитор, `Ctrl+Alt+S` настройки.

## Запуск

```bash
node app/server.js          # http://0.0.0.0:4173
# или
npm --prefix app start
```

Переменные окружения: `PORT` (по умолчанию `4173`), `HOST` (по умолчанию `0.0.0.0`).

## Что умеет

| зона | функции |
|---|---|
| терминал | реальный `bash -c` в текущей папке, сохранение `cd` между командами, история `↑`/`↓`, `Ctrl+L` — очистка, `Ctrl+C` — прерывание процесса (SIGKILL всей группы) |
| privileges | индикатор `sudo -n`, тумблер **root mode** — все команды идут через `sudo -n`, приглашение меняется на `root@e2b:#` |
| system | ядро, CPU, load average, память, диск, uptime, версии node/python — обновление каждые 2 с |
| files | листинг каталога, переход по папкам, клик по файлу подставляет `cat '<path>'` в строку ввода |
| верхняя панель | хост, git-ветка, текущий каталог, состояние рабочего дерева, часы |

## API

```
GET  /api/stats        -> хост, CPU, память, диск, git, sudo
GET  /api/ping         -> { ok, pid }  (health-check)
POST /api/exec         { cmd, root?, cwd? } -> { out, cwd, code, ms }
POST /api/kill         { id }
GET  /api/exec?p=<b64> -> те же параметры через query, для прокси
GET  /api/files?path=  -> { path, parent, items[] }
GET  /api/read?path=   -> { text, size, mtime, binary }
POST /api/write        { path, text }
GET  /api/download?path=&inline=1
GET  /api/proc         -> таблица процессов
POST /api/killproc     { pid, signal, root }
GET  /api/fetch?url=   -> { status, contentType, text } (через curl)
```

## Транспорт (если «не удалось связаться с сервером»)

Превью-прокси иногда отвечает HTML вместо JSON или режет POST. Клиент
перебирает транспорты и запоминает рабочий:

```
POST /api/<name>  →  GET /api/<name>?p=<base64>  →  GET /api/<name>.json?p=…
                  →  POST /x/<name>  →  GET /x/<name>  →  GET /x/<name>.json?p=…
```

Кнопка **диагностика** в панели privileges прогоняет все шесть и печатает
результат. В консоли браузера видно `[sandbox-console] transport: GET /api/*.json`.

## Root

В контейнере `sudo -n` работает без пароля, поэтому root-доступ реальный:
`whoami` в root mode вернёт `root`, `id -u` → `0`. Внутри root mode команда
выполняется как `sudo -n bash -c '<команда>'`, при этом рабочий каталог
внешней сессии не меняется — `cd` в root-команде действует только внутри неё.

## Реальный GUI-стек

- **PTY**: `app/pty-bridge.py` делает `pty.fork()` и гоняет байты между псевдотерминалом
  и пайпами Node. Протокол — обычный HTTP long-poll (`/api/ptyopen|ptyread|ptywrite|ptyresize|ptyclose`),
  поэтому он проходит через любые превью-прокси, где не работает WebSocket.
- **Эмулятор**: `xterm.js 5.5` вендорен в `app/public/vendor/xterm/` (лицензия MIT, файл LICENSE рядом).
- **Оконный менеджер**: свой, на pointer events + CSS (`app/public/js/wm.js`).
- **X11/Wayland** в этой песочнице поднять нельзя: репозитории Debian недоступны
  (`apt-get update` упирается в сетевые лимиты), а без них нет `Xvfb`/`libnss3` —
  значит и настоящего Firefox/Chromium тоже. Поэтому «браузер» — это серверный
  `curl` + очистка HTML, а GUI-стек закрыт PTY-терминалом и оконным менеджером.

## Стили

`index.html` отдаётся сервером с **инлайн-встроенным** `style.css` (тег `<style id="inline-css">`).
Так интерфейс не разваливается, если прокси превью ломает/блокирует запросы к CSS.

## Безопасность

Сервер не имеет авторизации: любой, у кого есть ссылка на превью-порт,
получает shell с root-правами внутри сандбокса. Это инструмент локальной
разработки — не выставляй порт в публичный интернет и останови процесс, когда
закончишь.
