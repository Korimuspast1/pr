# RYU — спецификация формата (Ryuu Notation), версия 1.0

**RYU** (Ryuu Notation, «нотация дракона») — человекочитаемый текстовый формат
структурированных данных. Расширение файла: `.ryu`. MIME-тип: `text/x-ryuu`.
Кодировка: UTF-8.

## 1. Философия

JSON, YAML, TOML, CSV и XML описывают данные как *текст с разметкой*:
скобки, кавычки, двоеточия, запятые, значимые отступы. RYU описывает данные
как **обход дерева курсором**: документ — это тропа; каждая строка — один
шаг; руна в начале строки говорит, что за шаг.

Отсюда свойства формата:

* **одна строка — один узел** (легко диффать, логировать, стримить);
* **нет кавычек** — строки записываются как есть, экранирование не нужно;
* **нет скобок, запятых и двоеточий** — вложенность выражается стеком
  открытых узлов, а не парными символами;
* **отступы не значимы** — нельзя «сломать» документ пробелом;
* **типы размечены рунами** — число, время, ссылка и байты различимы
  визуально и для парсера без вывода типов;
* **однопроходный разбор** за O(число строк) без lookahead.

## 2. Модель данных

Дерево из трёх видов узлов:

| Вид        | Представление в Python | Аналог JSON      |
|------------|------------------------|------------------|
| карта      | `dict` (порядок сохраняется) | object     |
| список     | `list`                 | array            |
| атом       | см. §6                 | string/number/…  |

Корнем документа может быть любой узел: карта, список или атом.
Пустой документ разбирается как `null`.

## 3. Структура документа

Документ — последовательность строк, разделённых `\n` (при чтении `CRLF` и
одиночный `CR` нормализуются в `LF`; UTF-8 BOM допускается и отбрасывается).

* **Пустая строка** игнорируется (кроме строк внутри блока `~~~`).
* **Комментарий** — строка, первый значащий символ которой `;`. Комментарии
  только целыми строками: `;` внутри значения — обычный символ.
* **Инструкция** — всё остальное. Формат инструкции:

```
[подъёмы] руна [нагрузка]
```

Подъёмы — это одна и более апострофов `'` в начале (после незначащих
пробелов). Пробелы в начале и конце строки не значимы (снова же — кроме
блоков `~~~`).

## 4. Руны

| Руна | Имя          | Назначение                                        |
|------|--------------|---------------------------------------------------|
| `'`  | взлёт        | закрыть один открытый узел (можно `''`, `'''`…)   |
| `.`  | гнездо       | открыть именованное поле карты                    |
| `+`  | элемент      | открыть элемент списка                            |
| `~`  | нить         | строка (сырая, до конца строки)                   |
| `#`  | число        | целое / float / hex / bin / oct / inf / nan       |
| `?`  | флаг         | булево значение                                   |
| `%`  | мгновение    | дата / время / дата-время (ISO-8601)              |
| `&`  | тропинка     | ссылка: URL / URI / путь                          |
| `!`  | пустота      | `null`, без нагрузки                              |
| `$`  | груз         | байты, base64                                     |
| `\|` | форма        | пустая карта `\| map` или пустой список `\| list` |
| `;`  | шёпот        | комментарий (целой строкой)                       |
| `~~~`| клубок       | блочная строка: строки подряд до закрывающего `~~~` |

**Правило одного пробела**: после руны (или после имени поля перед
инлайн-атомом) пропускается ровно один пробел/таб. Всё дальнейшее —
нагрузка. Так сохраняются ведущие пробелы в строках:
`~   x` — это строка `"  x"`.

## 5. Семантика: стек открытых узлов

Разбор ведётся стеком «открытых» узлов. В каждый момент курсор стоит
внутри верхнего узла стека.

### 5.1. Корень

Тип корня определяется первой инструкцией:

* `. имя` — создаётся неявная корневая карта;
* `+` — создаётся корневой список;
* атом — корень-атом (документ из одного значения).

После закрытия корня (подъёмом или атомом) любые дальнейшие инструкции —
ошибка «data after document root».

### 5.2. Гнездо `.`

```
. имя                 открыть поле-контейнер
. имя рунa значение   поле-лист: атом в ту же строку
```

* Имя — один токен без пробелов; не может начинаться с руны
  (`'.,~#?%&!$|;+`). Дубликаты имён в одной карте — ошибка.
* `.` кладёт поле **в самый глубокий открытый узел** (правило
  «глубже некуда»): плоские объекты пишутся без единого подъёма.
* `.` не может жить в списке, поэтому перед `.` верхние узлы в режиме
  списка закрываются автоматически (см. §5.6).

### 5.3. Элемент `+`

```
+                 открыть элемент-контейнер
+ руна значение   элемент-лист: атом в ту же строку
```

* Первый `+` внутри гнезда/элемента превращает этот узел в список.
* `+` — «следующий элемент»: если верхний узел уже заполнен, `+`
  закрывает всё до **внутреннего списка** и открывает элемент в нём
  (разделитель записей — как перевод строки в CSV, только явный).
* Если заполненный узел — поле-карта, а списка в стеке нет, `+` — ошибка:
  поле не может быть одновременно картой и списком.
* Повторный `+` в уже закрытое (поднятое) гнездо-список — ошибка:
  закрытый список не открывается повторно.

### 5.4. Атомы

Атом привязывается к верхнему узлу стека:

| Верхний узел        | Действие                                   |
|---------------------|--------------------------------------------|
| гнездо/элемент (пустой) | атом становится значением, узел закрывается |
| список              | атом дописывается элементом, список остаётся открытым («голодный» список) |
| пустой стек         | атом — скалярный корень                    |

Атом «запечатывает» своё гнездо: после `. age` + `# 30` курсор снова в
родителе. Именно поэтому плоские карты не требуют подъёмов.

### 5.5. Взлёт `'`

`'` закрывает ровно один верхний узел; `''` — два, и так далее. Подъём на
пустом стеке — ошибка. Корень можно закрыть подъёмом явно; тогда конец
файла должен наступить немедленно.

### 5.6. Авто-закрытие

Часть «строительных лесов» строится и разбирается сама:

1. **Перед `.`** верхние узлы в режиме списка (списки и их держатели)
   закрываются автоматически — поле не может попасть в список.
2. **Перед `+`** заполненные узлы закрываются до внутреннего списка
   (разделитель записей).
3. **Атом** закрывает своё гнездо-лист (§5.4).
4. **Конец файла** закрывает все открытые узлы.

Правила финализации закрытого узла:

| Узел в момент закрытия            | Значение            |
|-----------------------------------|---------------------|
| есть атом                         | атом                |
| есть дети-поля                    | карта               |
| есть дети-элементы                | список              |
| гнездо без детей                  | пустая карта `{}`   |
| элемент без детей                 | выбрасывается (леса); нужен `null` — пишите `+ !` |

### 5.7. Блочная строка `~~~`

Строка, состоящая (после обрезки пробелов) из `~~~`, открывает блок.
Все строки до следующей такой же — содержимое, дословно: пробелы, `;`,
руны — всё сохраняется. Значение — строки, соединённые `\n` (без
завершающего перевода). Блок — обычный атом (§5.4). Незакрытый блок —
ошибка.

## 6. Атомы

### 6.1. Строка `~`

Сырая строка до конца строки. Экранирования нет и не будет: то, что видно
в файле, то и есть значение. Переводы строк — только через блок `~~~`.
Ведущие пробелы сохраняются благодаря правилу одного пробела; замыкающие
пробелы — тоже часть значения (не оставляйте их случайно).

### 6.2. Число `#`

```
# 42        # -7        # +5        # 007        # 1_000_000
# 3.14      # -0.5      # .5        # 1e3        # 1.5e-3
# 0x1F      # 0b1010    # 0o17      # inf        # nan
```

Целые: десятичные, `0x`/`0b`/`0o`, знак, `_`-разделители. Числа с точкой
или экспонентой — float. Ведущий `+` допускается. Каноническая запись:
целые без всего, float всегда с `.` или `e` (`1.0`, а не `1`).

### 6.3. Флаг `?`

`yes/no/true/false/on/off/1/0`, регистр не важен. Канонически: `yes`/`no`.

### 6.4. Мгновение `%`

ISO-8601: дата `% 2026-09-28`, время `% 14:30:59`, дата-время
`% 2026-09-28T14:30:59Z`, `% 2026-09-28T14:30:59+03:00`. Тип
сохраняется: дата остаётся датой (не превращается в полночь).

### 6.5. Тропинка `&`

Ссылка — URL, URI или путь: `& https://…`, `& ./depot.cache`,
`& #section`. Тип отличается от строки, чтобы round-trip не терял
семантику.

### 6.6. Груз `$`

Байты в base64: `$ aGVsbG8=`. Пробелы внутри игнорируются.

### 6.7. Пустота `!` и форма `|`

`!` — `null`, без нагрузки. `| map` — пустая карта, `| list` — пустой
список (явная «полая форма», в том числе инлайн: `. dlc | list`).

## 7. Каноническая запись

Референсный писатель (`ryuu.dumps`) выдаёт единственную каноническую
форму, пригодную для побайтового сравнения и подписи:

* поля-листы — одной строкой `. имя руна значение`;
* элементы-листы — одной строкой `+ руна значение`;
* контейнеры — строкой-заголовком и детьми ниже;
* подъёмы — минимальные: writer пользуется авто-закрытием
  (§5.6), поэтому в списках записей подъёмов нет вовсе;
* числа — канонические (§6.2), булевы — `yes`/`no`, даты — `isoformat()`;
* строки с `\n` — блоком `~~~`;
* порядок ключей карты сохраняется;
* файл завершается одиночным `\n`.

`loads(dumps(x)) == x` для любого представимого `x`, и
`dumps(loads(dumps(x))) == dumps(x)` (идемпотентность).

## 8. Грамматика (EBNF)

```
document    = { line } ;
line        = blank | comment | instruction ;
blank       = [ ws ] NL ;
comment     = [ ws ] ";" { any } NL ;
instruction = [ ws ] lift { lift } node NL ;
lift        = "'" ;
node        = field | item | atom | block ;

field       = "." ws name [ ws atom ] ;            (* name = токен без пробелов *)
item        = "+" [ ws atom ] ;
atom        = "~" [ " " raw ]                      (* строка, сырая *)
            | "#" ws number
            | "?" ws boolean
            | "%" ws iso8601
            | "&" ws uri
            | "!"
            | "$" ws base64
            | "|" ws ( "map" | "list" ) ;
block       = "~~~" NL { raw_line } "~~~" ;
```

(`NL` — перевод строки; `ws` — пробелы/табы; `raw`/`raw_line` — любые
символы до конца строки.)

## 9. Ошибки

Все ошибки разбора — `RyuuParseError` с номером строки. Основные:

| Сообщение                                     | Причина                              |
|-----------------------------------------------|--------------------------------------|
| `unknown rune`                                | строка начинается не с руны          |
| `field without a name`                        | `.` без имени                        |
| `duplicate field`                             | два одноимённых поля в одной карте   |
| `field name must not start with a rune`       | имя вроде `~x`                       |
| `unexpected trailing payload after field name`| мусор после имени                    |
| `field already holds a map — it cannot become a list` | `+` в заполненном поле без списка |
| `field already holds a list — a closed list cannot be reopened` | `+` после закрытия списка |
| `lift with nothing open`                      | лишние `'`                           |
| `data after document root`                    | инструкции после закрытия корня      |
| `unterminated block string`                   | блок `~~~` не закрыт                 |
| `bad number` / `bad boolean` / `bad date/time` / `bad base64` / `bad hollow form` | неверная нагрузка атома |

Ошибки записи (`RyuuWriteError`): ключ с пробелом, пустой ключ, ключ с
руны, неподдерживаемый тип, строка, содержащая строку `~~~`.

## 10. Сравнение

| Свойство                        | JSON | YAML | TOML | CSV | RYU  |
|---------------------------------|------|------|------|-----|------|
| кавычки для строк               | да   | иногда | иногда | да | **нет** |
| парные скобки                   | да   | нет  | нет  | —   | **нет** |
| значимые отступы                | нет  | да   | нет  | нет | **нет** |
| запятые между элементами        | да   | нет  | нет  | да  | **нет** |
| размеченные типы атомов         | нет  | нет  | нет  | нет | **да** (время, ссылка, байты) |
| многострочный текст без escape  | нет  | да   | нет  | нет | **да** (`~~~`) |
| комментарии                     | нет  | да   | да   | нет | **да** |
| потоковый однопроходный разбор  | да   | сложный | да | да | **да** |
| таблицы/записи                  | нет  | нет  | нет  | да  | **да** (корень-список, `+` — разделитель записей) |

## 11. Ограничения (сознательные)

* **Имена полей — один токен**: без пробелов и не с руны. Это цена отказа
  от кавычек. Пишите `release_date` вместо `release date`.
* **Комментарии только целыми строками** — иначе пришлось бы экранировать
  `;` в строках.
* **Замыкающие пробелы строк значимы** — следствие сырости строк.
* **Строка не может содержать строку `~~~`** (оборвала бы блок). В остальном
  escape не нужен.
* **Пустой элемент выбрасывается** — используйте `+ !` для явного `null`.
* **Закрытый список не открывается повторно** — предотвращает двусмысленность.

## 12. Референс-реализация

Python-пакет `ryuu` в этом же репозитории (`ryuu/parser.py`,
`ryuu/writer.py`): ~700 строк, ноль зависимостей. Тесты:
`python3 -m unittest discover -s tests` (70 тестов, включая 300
псевдослучайных деревьев на round-trip).
