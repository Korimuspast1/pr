# Wave — музыкальный сервис

Свой музыкальный сервис: ищешь трек — он ищется по каталогу SoundCloud (и по
бесплатным каталогам Creative Commons), попадает в твоё приложение, и его можно
слушать. Без сборки, без базы, без npm-зависимостей: `node server.js` и всё.

```
┌──────────────────────────────────────────────────────────┐
│ Wave  поиск музыки          [ что послушаем? … ]  [Найти] │
│  ⌕ Поиск        ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐      │
│  ♥ Избранное    │ art  │ │ art  │ │ art  │ │ art  │      │
│  ↻ История      │трек  │ │трек  │ │трек  │ │трек  │      │
│                 └──────┘ └──────┘ └──────┘ └──────┘      │
│  ● SoundCloud                                            │
│  ● Jamendo      ┌──────────────────────────────────────┐  │
│  ● Archive      │ ▶  трек — артист   ──────○──── 2:41 │  │
└──────────────────────────────────────────────────────────┘
```

## Запуск

```bash
cd wave
npm start            # http://localhost:3000
```

Node 20+. Больше ничего ставить не нужно — зависимостей нет вообще.
Тесты: `npm test` (парсеры SoundCloud, валидация ссылок, HTTP-роуты, защита путей).

### Переменные окружения

| Переменная | Что делает |
|---|---|
| `PORT` / `HOST` | адрес сервера, по умолчанию `0.0.0.0:3000` |
| `SOUNDCLOUD_CLIENT_ID` | включает официальный поиск через `api.soundcloud.com` (регистрация приложения на soundcloud.com/you/apps). Без ключа поиск идёт по публичным страницам SoundCloud — тоже работает |
| `JAMENDO_CLIENT_ID` | включает Jamendo: миллионы треков под Creative Commons, **играют прямо в приложении**. Бесплатный ключ: devportal.jamendo.com |
| `ARCHIVE_COLLECTIONS` | коллекции Internet Archive для поиска (по умолчанию `netlabels,audio_music,opensource_audio,78rpm`) |
| `WAVE_USER_AGENT` | нормальный User-Agent для запросов к каталогам |
| `WAVE_DEBUG=1` | показывать stack в ответах об ошибках |

## Что умеет

- **Поиск по SoundCloud** — название, артист, жанр, обложки, длительность;
  результат нормализуется в общий формат `{title, artist, artwork, durationSec, url, …}`.
- **Поиск по Jamendo и Internet Archive** — там музыка под CC/общественным
  достоянием, поэтому её можно **стримить прямо в приложении** через
  `/api/audio` (с поддержкой Range → работает перемотка).
- **Плеер**: play/pause, перемотка, громкость, следующий/предыдущий, пробел,
  автопереход, «сейчас играет».
- **Офлайн-демо**: если каталоги недоступны (нет сети / провайдер молчит),
  сервер сам синтезирует три трека (`/api/demo/*.wav`, настоящий WAV с Range)
  и отдаёт их в поиск — интерфейс и плеер остаются живыми.
- **Избранное и история** — в `localStorage`, переживают перезагрузку.
- **Фильтр по источнику** (`Всё / SoundCloud / Jamendo / Archive`).
- Кэш поиска на 5 минут, rate-limit 60 запросов/мин на IP, таймауты на все
  внешние запросы, защита статики от path traversal.
- Мобильная вёрстка (можно добавить на домашний экран).

## Про «лазейки» в SoundCloud — честно

Просили найти лазейки, чтобы любые треки из SC играли в своём приложении.
Таких лазеек, которые не ломают ни закон, ни сервис, нет — и вот почему:

1. **SoundCloud Developer Terms прямо запрещают** вытаскивать поток в обход
   официального плеера: `stream`, `transcode`, внутренние `api-v2`-эндпоинты,
   кражу `client_id` из чужого веб-плеера. Приложение за это блокируют по
   `client_id`/IP, а аккаунт — по DMCA.
2. **Авторские права.** Большинство треков на SC — чужая музыка (ремиксы,
   загрузки релизов). Стрим в своём плеере без лицензии = нарушение.
   В Германии за это прилетает не абстрактный бан, а письмо от юристов.
3. Технически «лазейки» (тип `api-v2 resolve → …/stream/progressive` с
   вытащенным client_id) живут неделями: SC меняет схему, ключи отзывают,
   IP-банят. Строить сервис на этом — гарантированно чинить его каждый месяц.

Поэтому **как оно сделано здесь** — это максимум, который даёт SoundCloud:

| Что | Как |
|---|---|
| Поиск по всему SC-каталогу | публичный поиск `/search/sounds` + официальный API, если дашь `client_id` |
| Обложки, артист, жанр, длительность | из публичной страницы трека |
| Воспроизведение SC-трека | **официальный встраиваемый плеер** `w.soundcloud.com/player` внутри приложения — трек играет SoundCloud, артист получает статистику/выплаты, всё легально |
| Полноценный стрим в своём плеере | для музыки, у которой есть лицензия: Jamendo (CC) и Internet Archive (PD/CC) — играет нативно |
| Ссылка на трек/артиста | есть на каждой карточке |

Отдельно: **прокси через `soundcloud.com/oembed`** (`/api/embed`) сделан для
server-side рендеринга карточки и валидируется по белому списку — он не
отдаёт поток и не подменяет плеер.

### Если нужен именно «свой стриминг всего»

Легальные варианты, по возрастанию усилий:

1. **Добавить каталоги с лицензией** — Jamendo (уже есть), Free Music Archive,
   ccMixter, Audius (открытый API, CC-музыка), Bandcamp (только официальный
   embed). Это то же приложение, просто больше играющей музыки.
2. **Стать партнёром SoundCloud** — API-договор (`developers.soundcloud.com`)
   даёт официальный стрим для тех треков, где авторы разрешили.
3. **Свои загрузки** — раздел «загрузить трек» + файлы на диске (только своя
   музыка и/или с прямым разрешением автора).
4. **Метаданные всего мира без стрима** — MusicBrainz + Cover Art Archive:
   красивые карточки, а «играть» ведёт на легальный сервис (Spotify/Apple/SC).

## API

| Метод | Что |
|---|---|
| `GET /api/search?q=phonk&source=all&limit=24` | поиск. `source`: `all` \| `soundcloud` \| `jamendo` \| `archive` |
| `GET /api/providers` | какие источники включены |
| `GET /api/health` | аптайм и статус провайдеров |
| `GET /api/embed?url=https://soundcloud.com/artist/track` | официальный embed (oEmbed) |
| `GET /api/audio?u=<url>` | прокси CC/PD-аудио (белый список доменов, Range) |
| `GET /api/demo/<id>.wav` | локально сгенерированные демо-треки (`night-city`, `lofi-desk`, `morning-jazz`) |
| `GET /player?url=…` | страница с официальным плеером SoundCloud |

Пример:

```bash
curl 'http://localhost:3000/api/search?q=lofi&source=all' | head -c 600
```

## Структура

```
wave/
├── server.js          # HTTP-сервер, роуты, кэш, rate-limit, статика
├── src/
│   ├── soundcloud.js  # поиск по SoundCloud + парсеры + embed/oEmbed
│   ├── catalogs.js    # Jamendo, Internet Archive, прокси аудио
│   ├── demo.js        # синтез демо-треков в WAV (работает без сети)
│   └── util.js        # fetch с таймаутом, JSON-ответы, утилиты
├── public/            # интерфейс (index.html, app.js, styles.css, favicon)
└── test/smoke.mjs     # тесты без внешней сети
```

## Деплой

Любая машина с Node 20:

```bash
PORT=3000 HOST=0.0.0.0 JAMENDO_CLIENT_ID=xxxx node wave/server.js
```

Docker:

```bash
docker build -t wave wave
docker run -p 3000:3000 -e JAMENDO_CLIENT_ID=xxxx wave
```

Если ставишь за nginx и хочешь прокси аудио — не забудь `proxy_buffering off;`
для `/api/audio`, иначе перемотка будет дёргаться.

## Демо без интернета

Песочница/самолёт/упавший провайдер — не повод видеть пустой экран. Если
все каталоги молчат, поиск вернёт три трека, которые сервер синтезирует
сам (синусоиды + шум, 24 секунды, 22 кГц mono WAV): `Night City`,
`Lo-fi для работы`, `Morning Jazz`. Они честно помечены `Wave Demo`,
играют в нативном плеере, перематываются и переживают перезагрузку.

```bash
curl -o demo.wav 'http://localhost:3000/api/demo/night-city.wav'
```

## Ограничения

- Поиск без `SOUNDCLOUD_CLIENT_ID` зависит от разметки публичных страниц SC:
  если они её поменяют, парсер надо будет обновить (тесты подскажут, что именно).
- SC-треки играют **в официальном плеере внутри страницы**, а не в нижнем
  нативном плеере — это осознанно, см. раздел выше.
- Rate-limit на поиск в SoundCloud может отвечать 429 — приложение показывает
  это человеческим текстом и не падает.
